# Changelog

## 0.0.5-pre

- Исправлены production-проверка form/cookie-аутентификации bot-admin, адрес XHTTP-выхода для кластерной 3x-ui-ноды и выбор актуального source-root при установке заглушки.
- Добавлен рекомендуемый мастер VPS-1 + произвольное число зарубежных нод: сайт на текущей RU VPS, Telegram-бот на выбранной 3x-ui-ноде и сохранение всех существующих VPN-конфигураций.
- Перед изменениями обязательны read-only аудит и проверенные pre-change архивы всех ролей; существующие inbounds и клиенты контролируются стабильным отпечатком.
- Bot-admin на VPS-2 доступен только через loopback SSH-туннель, поддержаны отдельные SSH-порты, а vhost панели 3x-ui ограничивается адресом VPS-1 с rollback при ошибке `nginx -t`.
- Версия, default config, Telegram-меню, env-схемы и контракты трёх topology modes сведены в общие источники истины.
- Компонентные CLI используют общий lifecycle backend и manifest владения; purge сайта больше не удаляет backup 3x-ui, а purge бота удаляет egress unit/config и только записанных в manifest служебных клиентов.
- В mode 3 Xray fallback автоматически и идемпотентно направляет HTTPS на полный HOME-VPN; заглушка на управляющей ноде запрещена и `/health` проверяется через `public_url`.
- Bot-admin слушает только loopback и публикуется на закрытом path через TLS-вход сайта; внутренний API бота использует loopback.
- При полном отказе нод заказ не создаётся и API возвращает 503; распределение учитывает active users, незавершённые назначения, вес, maintenance и `accept_new`.
- Выход из cascade удаляет только таблицу `ip home_vpn_cascade`, unit, nft-файл и sysctl drop-in, восстанавливая прежний `ip_forward`; это выполняется и при переходе 2→3.
- Разделены backup 3x-ui, состояния сайта и состояния бота; добавлена проверяемая распаковка и обязательное age-шифрование при включении секретов.
- Добавлены schema/unit/integration-smoke проверки, таблица портов/firewall и migration guide с 0.0.4-pre.

## 0.0.4-pre

- Архитектура переведена на центральную VPS (желательно RU) и произвольное число зарубежных VPS.
- На каждой зарубежной VPS устанавливаются 11 VPN-подключений, а Telegram-бот и все HOME-VPN web-панели работают на центральной VPS.
- Telegram API доступен боту через закрытый VLESS/XHTTP-пул: `roundRobin`, health-check, исключение недоступных выходов и запрет прямого обхода.
- Новые подписки распределяются по доступным зарубежным нодам с учётом нагрузки и веса, после чего закрепляются за выбранной нодой.
- На управляющей ноде всегда устанавливается полный сайт HOME-VPN; старая заглушка удаляется, а новые заглушки разрешены только на дополнительных нодах.
- Добавлен защищённый многосерверный мастер с прямым root SSH-доступом.
- Добавлено безопасное переключение `direct` / `cascade`: каскад использует
  путь `пользователь → центральная VPS → зарубежная VPS → интернет`.
- Старый HOME-VPN backup-server, exporter, локальный portable backup и связанные вкладки удалены.
- Резервирование унифицировано на штатном `kit backup` с автоматической проверкой TAR и SQLite.
- Настройки сайта синхронизируются с API всех VPN-нод; Emergency MTProto запускается по требованию активного клиента.

## 0.0.3-pre

- Резервный контур переведён с push на pull: production-узлы больше не имеют доступа к backup-хранилищу.
- Добавлены read-only SSH exporter, центральный планировщик, шифрование архивов, GFS retention и off-site репликация.
- Добавлены автоматическая повторная проверка целостности, мониторинг пропусков/диска и выборочное восстановление.
- Backup GUI получил управление pull-заданиями, ручной запуск и необязательную TOTP MFA.
- Добавлен взаимоисключающий выбор оплаты: ручное подтверждение администратора или автоматическая ЮKassa.
- Добавлена безопасная серверная проверка уведомлений ЮKassa, идемпотентное создание платежа и автоматическая выдача подписки.
- Сайт и Telegram-бот показывают единый активный способ оплаты.
- Локальные копии, Backup-агент и ссылка на центральный Backup-сервер объединены в одну графическую панель администратора.
- Обновлена графическая панель Backup-сервера и мастер настройки секретов оплаты.
- В админ-панель добавлен отдельный раздел оплаты: ручная ссылка, Shop ID, секретный ключ, API URL и URL возврата.
- Настройки сайта автоматически используются подключённым Telegram-ботом; платёжные секреты в API бота не передаются.
- Автоматическое обновление из GitHub временно отключено; обновление из локального каталога сохранено.

## 0.0.2

- роли «Backup-сервер» и «Backup-агент» разделены в общем установщике;
- backup-сервер больше не требует ключ первого рабочего сервера при установке;
- в GUI добавлены отдельные кнопки «Добавить сервер» и «Удалить сервер»;
- добавлено временное отключение и повторное включение приёма копий;
- удаление сервера требует ввода его ID и отдельно предлагает удалить архивы;
- при безопасном удалении архивы переносятся в закрытый карантин;
- старые профили `0.0.1-pre` автоматически дополняются публичными ключами;
- установщик backup-агента проверяет SSH host key хранилища;
- обновление backup-агента сохраняет профиль, ключи и локальные архивы;
- добавлена полная инструкция чистой установки, обновления и внедрения в существующую систему.
- backup-панель получила выбор конкретного сервера и фильтры по типу регистрации;
- серверы теперь явно отмечаются как «добавлен в GUI» или «только обнаруженные архивы»;
- для обнаруженного каталога доступна регистрация в GUI с заранее заполненным ID;
- сводка отдельно показывает управляемые профили и старые каталоги архивов.
- серверы объединяются в карточки независимых конфигураций проекта;
- внутри конфигурации отдельно показаны сайт, Telegram-бот, основная и дополнительные 3x-ui-ноды;
- архивы остаются разделёнными по серверам и раскрываются внутри общей карточки;
- добавлены создание и редактирование состава конфигурации через GUI.
