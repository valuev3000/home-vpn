# Мультисерверное резервное хранилище

Компонент предназначен для отдельного сервера со стабильным публичным IP. Один
backup-сервер принимает независимые копии основной RU-ноды, PL-ноды, сервера
бота и тестового стенда. Каждый источник имеет собственный SSH-ключ, ID,
каталог и срок хранения.

## Архитектура безопасности

Источники сами отправляют архивы на backup-сервер. Backup-сервер не хранит
root-ключи доступа к рабочим серверам и не может самостоятельно войти на них.
Для каждого публичного ключа SSH принудительно запускает только проверяющий
приёмник архива. Интерактивная оболочка этим ключом недоступна.

Панель использует:

- встроенный HTTPS на порту `9443`;
- отдельный закрытый URL;
- отдельные логин и пароль;
- защищённую cookie и CSRF-проверку;
- ограничение попыток входа;
- отдельный root-helper с фиксированным списком операций.

При публикации наружу разрешите:

- `22/tcp` только с IP серверов, отправляющих копии;
- `9443/tcp` только с административных IP, если это возможно.

Самоподписанный тестовый сертификат необходимо заменить сертификатом публичного
домена. Пути задаются в `/etc/home-vpn-backup-panel.env`:

```text
BACKUP_PANEL_TLS_CERT=/path/to/fullchain.pem
BACKUP_PANEL_TLS_KEY=/path/to/privatekey.pem
```

После замены выполните:

```bash
sudo systemctl restart home-vpn-backup-panel
```

## Учётные данные

При установке закрытый URL, логин и пароль сохраняются только здесь:

```text
/root/home-vpn-backup-panel-credentials.txt
```

Файл имеет права `600`. Не помещайте его в Git и не отправляйте в общий чат.

## Подключение нового сервера

На источнике установите агент:

```bash
sudo python3 backup-node/install-full-backup-agent.py \
  --server-id prod-ru \
  --server-name "Основной RU" \
  --role site \
  --remote homevpnbackup@BACKUP_PUBLIC_IP
```

Роли:

- `site` — сайт, основная 3x-ui, базы, сертификаты и конфигурация;
- `bot` — Telegram-бот, панель бота и дополнительная 3x-ui;
- `node` — отдельная 3x-ui-нода.

Установщик выведет публичный ключ. В панели нажмите **Добавить сервер**,
укажите ID, имя, роль, ожидаемый адрес, ключ и срок хранения. После
этого на источнике выполните:

```bash
sudo systemctl start home-vpn-full-backup.service
sudo systemctl status home-vpn-full-backup.service
```

Ежедневный таймер:

```bash
systemctl status home-vpn-full-backup.timer
```

## Что находится в архиве v2

- согласованные SQLite-копии;
- конфигурация сайта, бота и 3x-ui;
- TLS-сертификаты и закрытые ключи;
- systemd unit-файлы;
- код установленных компонентов;
- изображения инструкций;
- список пакетов и исходный hostname;
- SHA-256 каждого файла.

Крупные установщики HAPP из `/srv/home-vpn/downloads` намеренно не копируются
ежедневно: они не являются пользовательскими данными и быстро заполнили бы диск.
После переезда их следует скачать или развернуть повторно.

Архив содержит секреты. Он хранится с правами `600`; доступ к панели и SSH
нужно строго ограничить.

## Управление из GUI

Панель показывает:

- карточки независимых конфигураций, объединяющие сайт, бота и 3x-ui-ноды;
- отдельные раскрывающиеся архивы каждого сервера внутри общей конфигурации;
- все зарегистрированные и обнаруженные серверы;
- отдельную отметку «добавлен в GUI» или «только обнаруженные архивы»;
- выпадающий список конкретного сервера и фильтр по типу регистрации;
- свежесть последней копии;
- число архивов и занятое место;
- формат `v2`, `legacy` или повреждённый архив;
- общий и свободный объём диска.

Доступны операции:

- создать конфигурацию и изменить список входящих в неё серверов;
- добавить сервер, отключить или повторно включить его SSH-ключ;
- удалить сервер через отдельную форму с подтверждением его ID;
- проверить структуру, SHA-256 и SQLite;
- скачать архив;
- открыть инструкцию восстановления;
- удалить конкретный архив.

Отключение сервера временно отзывает его ключ, но сохраняет профиль и архивы.
Безопасное удаление профиля переносит архивы в
`/srv/home-vpn-backups-removed`; отдельный флажок позволяет безвозвратно удалить
и сами архивы.

## Полное восстановление при переезде

Архив v2 восстанавливает состояние приложения, а не образ всей операционной
системы. На новом сервере сначала установите совместимую Debian/Ubuntu, Python,
3x-ui и системных пользователей проекта.

1. Скачайте архив из GUI.
2. Скопируйте `backup-node/home-vpn-full-restore.py` на новый сервер как
   `/usr/local/sbin/home-vpn-full-restore`.
3. Сначала выполните только проверку:

   ```bash
   sudo home-vpn-full-restore /root/prod-ru-YYYYMMDD-HHMMSS.tar.gz
   ```

4. После успешной проверки выполните восстановление:

   ```bash
   sudo home-vpn-full-restore /root/prod-ru-YYYYMMDD-HHMMSS.tar.gz \
     --apply --replace-host=OLD_IP=NEW_IP
   ```

5. Введите `RESTORE`.
6. Обновите DNS, TLS, firewall, адреса нод и Telegram webhook/API URL.
7. Проверьте сайт, 3x-ui, выдачу тестовой подписки и Telegram-бот.
8. Старый сервер выключайте только после полной проверки нового.

Для побитовой копии всего LXC дополнительно используйте `vzdump` на Proxmox.
Переносимый архив v2 нужен для восстановления на другом VPS, другом IP или
чистой ОС без зависимости от конкретного хранилища Proxmox.
