# HOME-VPN 0.0.1-pre

Первая предварительная версия единого установщика. Она предназначена для
тестового стенда и обязательной проверки на резервной машине перед production.

## Запуск

```bash
git clone https://github.com/YOUR_ACCOUNT/home-vpn.git
cd home-vpn
sudo bash install.sh
```

Главное меню выполняет пять групп операций:

1. проверка уже установленных компонентов;
2. установка выбранных компонентов;
3. обновление программного кода без замены `.env`, баз и меню бота;
4. перенастройка сайта, домена, TLS, 3x-ui и заглушки;
5. полное удаление выбранных компонентов.

Компоненты выбираются по одному, списком через запятую или командой `all`:

- сайт и API;
- Telegram-бот и отдельная панель;
- домен и TLS;
- новый VLESS inbound в существующей 3x-ui;
- локальный сайт-заглушка;
- SMTP/IMAP;
- отдельный backup-сервер.

Статус без интерактивного меню:

```bash
python3 scripts/home-vpn-manager.py status
```

Примеры автоматического выбора:

```bash
sudo HOME_VPN_SOURCE_ROOT="$PWD" python3 scripts/home-vpn-manager.py install site placeholder
sudo HOME_VPN_SOURCE_ROOT="$PWD" python3 scripts/home-vpn-manager.py update site bot
sudo HOME_VPN_SOURCE_ROOT="$PWD" python3 scripts/home-vpn-manager.py configure domain xui
```

## VLESS и XHTTP

До запуска мастера установите 3x-ui, получите API-токен, подготовьте домен и
доверенный TLS-сертификат. В меню выберите компонент **VLESS inbound в 3x-ui**.

Мастер:

1. подключается к API 3x-ui и читает существующие inbound;
2. предлагает `xhttp` или `reality`;
3. проверяет, что выбранный порт не используется;
4. для REALITY генерирует X25519-ключи и Short ID, а тестового клиента создаёт
   только по отдельному подтверждению;
5. показывает безопасный предварительный просмотр;
6. только после явного подтверждения создаёт новый inbound;
7. добавляет созданный inbound в основную ноду `/etc/home-vpn/config.json`, если
   сайт уже установлен.

Существующие inbound не изменяются и не удаляются.

### XHTTP + TLS

Для XHTTP требуются:

- домен, направленный на сервер;
- TLS fullchain и закрытый ключ;
- отдельный секретный путь, например `/random-long-path`;
- свободный порт;
- при необходимости локальная заглушка на `127.0.0.1:8181`.

Обычный посетитель домена должен видеть сайт или заглушку, а XHTTP-клиент —
использовать только секретный путь. Конкретная схема совместного использования
порта 443 зависит от версии Xray/3x-ui и уже установленного reverse proxy.
Установщик не ставит Nginx автоматически. Перед production проверьте открытие
главной страницы и подключение клиента отдельно.

### REALITY

REALITY требует внешний TLS-target, например `www.cloudflare.com:443`. Нельзя
указывать тот же сервер целью самому себе: это создаёт цикл и не является
корректной заглушкой. Локальный сайт-заглушка применяется прежде всего для
XHTTP/TLS и обычных запросов к домену.

## Обновление

Обновление сайта сначала запускает резервное копирование, затем заменяет только
программный код и unit-файлы. Сохраняются:

- `/var/lib/vpn-shop/shop.db`;
- `/etc/vpn-shop.env`;
- `/etc/home-vpn/config.json`;
- `/etc/vpn-bot.env`;
- `/etc/vpn-bot-admin.env`;
- `/etc/vpn-bot-menu.json`.

После обновления перезапускается только соответствующая служба.

## Полное удаление

Удаление требует точной фразы:

```text
DELETE HOME-VPN
```

По умолчанию удаляются программы и службы, а базы и настройки сохраняются.
Дополнительный вопрос предлагает удалить данные, конфигурацию и локальные
резервные копии. Это необратимо.

Менеджер никогда автоматически не удаляет 3x-ui, её базу, сертификаты или
inbound. Почтовые пакеты и системный почтовый пользователь также сохраняются,
чтобы не уничтожить почту, не принадлежащую проекту.

## Откат

Перед обновлением:

```bash
sudo home-vpn-restore create
sudo home-vpn-restore list
```

После неудачного обновления:

```bash
sudo home-vpn-restore restore home-vpn-YYYYMMDD-HHMMSS.tar.gz all
```

Сначала проверяйте восстановление на отдельном тестовом сервере.
