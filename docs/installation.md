# Полная установка HOME-VPN

Версия мастера: **0.0.3-pre**. Актуальная инструкция обновления находится в
[installation-0.0.3-pre.md](installation-0.0.3-pre.md). Базовая полная инструкция 0.0.2 сохранена как
дополнительное описание отдельных компонентов.

Инструкция использует только примеры. Замените их своими значениями:

| Назначение | Пример |
|---|---|
| Основной сервер | `192.168.1.50` |
| Сервер Telegram-бота | `192.168.1.51` |
| Почтовый сервер | `192.168.1.52` |
| Backup-сервер | `192.168.1.53` |
| Сайт | `vpn.my.domain.ru` |
| Почта | `mail.my.domain.ru` |
| Адрес поддержки | `support@my.domain.ru` |

Для тестового стенда роли можно совместить. Для реальной установки рекомендуется
разнести сайт/основную 3x-ui, Telegram-бот и backup-сервер. Почту можно разместить
отдельно или использовать внешний SMTP/IMAP.

## 1. Требования

- Debian 12/13 или Ubuntu 24.04;
- root-доступ или `sudo`;
- минимум 2 ГБ RAM для основной ноды с 3x-ui;
- публичный домен и доверенный TLS-сертификат;
- установленная и работающая 3x-ui перед установкой сайта;
- отдельные API-токены 3x-ui для каждой ноды;
- Telegram Bot Token и цифровой Telegram ID администратора, если нужен бот.

Не публикуйте `.env`, базы SQLite, сертификаты, закрытые URL входа, API-токены
3x-ui и Telegram Bot Token.

## 2. DNS сайта

Создайте у DNS-провайдера:

```text
A  vpn.my.domain.ru   EXTERNAL_IP
```

Если почтовый сервер собственный, дополнительно нужны записи из
`mail-server/public-dns.example.txt` и PTR/rDNS у хостинг-провайдера.

## 3. Получение проекта

На каждом сервере, где будет установлен компонент:

```bash
sudo apt update
sudo apt install -y git python3
git clone https://github.com/YOUR_ACCOUNT/home-vpn.git
cd home-vpn
sudo bash install.sh
```

Мастер сначала предлагает действие: проверить состояние, установить, обновить,
перенастроить или полностью удалить. После этого выбираются компоненты: сайт,
бот, домен/TLS, VLESS в 3x-ui, заглушка, почта и backup-сервер.

## 4. Основной сервер: сайт и 3x-ui

Сначала установите 3x-ui официальным способом, создайте inbound и API-токен.
Убедитесь, что панель работает:

```bash
sudo systemctl status x-ui
```

Затем выберите пункт `1` в `install.sh`. Мастер запросит:

- публичный URL, например `https://vpn.my.domain.ru`;
- сертификат и закрытый ключ;
- логин и пароль администратора;
- тестового пользователя;
- адрес основной и дополнительных 3x-ui-нод;
- имя переменной окружения и токен каждой ноды;
- Telegram и почтовые параметры, если эти компоненты находятся на том же сервере.

Если публичный порт свободен, приложение использует встроенный HTTPS. Если порт
занят уже существующим reverse proxy, сайт запускается на `127.0.0.1:8080`.
Проект не устанавливает Nginx автоматически.

После установки:

```bash
sudo home-vpn-setup doctor
sudo systemctl status vpn-shop x-ui
curl -k https://127.0.0.1:443/health
```

Для нестандартного HTTPS-порта укажите его в команде `curl`.

Секреты находятся в `/etc/vpn-shop.env`, общая конфигурация — в
`/etc/home-vpn/config.json`. Оба файла не должны попадать в Git.

## 5. Telegram-бот на отдельном сервере

На основном сервере получите `API_SECRET`:

```bash
sudo grep '^API_SECRET=' /etc/vpn-shop.env
```

Не отправляйте его в общий чат и не сохраняйте в репозитории. На сервере бота
запустите `sudo bash install.sh`, выберите пункт `2` и укажите:

- `https://vpn.my.domain.ru` как публичный URL;
- тот же адрес как API сайта либо отдельный внутренний API URL;
- `API_SECRET` основного сервера;
- новый Telegram Bot Token;
- цифровой Telegram ID администратора;
- канал технических уведомлений;
- закрытый полный URL входа администратора.

Проверка:

```bash
sudo systemctl status vpn-bot
sudo journalctl -u vpn-bot -n 50 --no-pager
```

Секреты бота хранятся в `/etc/vpn-bot.env` с правами `600`.

### Отдельная панель управления ботом

Установщик одновременно создаёт службу `vpn-bot-admin` на `127.0.0.1:8090` и
показывает одноразово закрытый URL, логин и пароль. Опубликуйте её отдельным
доменом, например `https://bot-admin.my.domain.ru`, через уже установленный
reverse proxy либо добавьте доверенный TLS перед открытием порта наружу.

Панель позволяет:

- видеть состояние службы бота, Telegram API и основного сайта;
- просматривать последние записи журнала без отображения токена;
- запускать, останавливать и перезапускать бота;
- отправлять тестовое сообщение Telegram-администратору;
- менять заголовок и текст приветствия;
- переименовывать пользовательские кнопки;
- менять порядок кнопок стрелками или перетаскиванием;
- показывать или скрывать отдельные пункты меню;
- применять настройки с автоматическим безопасным перезапуском бота.

Настройки меню хранятся отдельно от программы в `/etc/vpn-bot-menu.json`.
Повторная установка или обновление кода не заменяет этот файл. Панель не даёт
редактировать callback-команды и URL кнопок, поэтому через подпись нельзя
подставить произвольное действие или внешнюю ссылку.

На основном сервере добавьте в `/etc/vpn-shop.env` полный закрытый URL панели:

```text
BOT_ADMIN_URL=https://bot-admin.my.domain.ru/private-bot-control-path
```

После `sudo systemctl restart vpn-shop` в админ-навигации появится кнопка
**Панель бота**. Root-команды панели ограничены отдельным sudoers-файлом и не
принимают произвольные команды.

### Логика установки бота и панели

При выборе компонента `2` файл `install.sh` запускает
`scripts/home-vpn-components.py bot`. Установщик последовательно:

1. запрашивает URL сайта и API, `API_SECRET`, Bot Token, Telegram ID
   администратора и канал;
2. запрашивает домен панели, локальный адрес, порт, логин и пароль;
3. создаёт системного пользователя `vpnshopbot` без интерактивной оболочки;
4. устанавливает программу в `/opt/vpn-bot`, а systemd-службы — в
   `/etc/systemd/system`;
5. сохраняет секреты в `/etc/vpn-bot.env` и `/etc/vpn-bot-admin.env` с правами
   `600`;
6. создаёт `/etc/vpn-bot-menu.json` с правами `640`, если файла ещё нет;
7. устанавливает строго ограниченный helper `/usr/local/sbin/vpn-bot-admin-control`
   и проверяет его правило через `visudo`;
8. включает и запускает `vpn-bot` и `vpn-bot-admin`.

Редактор панели передаёт helper только заранее разрешённые действия. При
сохранении helper проверяет длину текста, полный набор пунктов, атомарно заменяет
JSON и перезапускает только службу `vpn-bot`. Telegram-токен через панель не
читается и не отображается.

Ручная проверка после установки:

```bash
sudo systemctl status vpn-bot vpn-bot-admin
sudo -u vpnshopbot sudo /usr/local/sbin/vpn-bot-admin-control status
sudo -u vpnshopbot sudo /usr/local/sbin/vpn-bot-admin-control get-menu
```

## 6. Почтовый сервер

На отдельном сервере выберите пункт `3`. Мастер запросит домен, hostname,
почтовый адрес и локальный IP. Устанавливаются Postfix, Dovecot, OpenDKIM и
Fail2ban. Открываются сервисы:

- `25/tcp` — приём почты между серверами;
- `465/tcp` — SMTP over TLS;
- `587/tcp` — SMTP submission с авторизацией;
- `993/tcp` — IMAPS.

Пароль ящика сохраняется только в `/root/home-vpn-mail-credentials.txt`.
Самоподписанный сертификат установщика предназначен для тестов. Для production
замените его доверенным сертификатом `mail.my.domain.ru`.

На сайте откройте **Админ-панель → Почта → Настроить SMTP и IMAP** и укажите:

```text
SMTP: mail.my.domain.ru, порт 587, STARTTLS
IMAP: mail.my.domain.ru, порт 993, SSL/TLS
Логин: support
Отправитель: support@my.domain.ru
```

## 7. Отдельный backup-сервер

Новая мультисерверная HTTPS-панель, подключение независимых RU/PL-источников и
полное восстановление при переезде описаны в
[multi-server-backup.md](multi-server-backup.md).

На отдельном backup-сервере запустите мастер и выберите компонент
**Backup-сервер и GUI**:

```bash
sudo bash install.sh
```

На каждом рабочем сервере выберите **Backup-агент рабочего сервера**. После
установки вставьте показанный публичный ключ через кнопку **Добавить сервер** в
backup-панели. Подробный актуальный сценарий находится в
[installation-0.0.2.md](installation-0.0.2.md#9-подключение-первого-и-последующих-серверов-к-backup).

Проверка на основном сервере:

```bash
sudo systemctl start home-vpn-full-backup.service
sudo systemctl status home-vpn-full-backup.service --no-pager
sudo systemctl status home-vpn-full-backup.timer --no-pager
```

## 8. Первичная настройка через админ-панель

После входа настройте:

1. **Настройки сервиса** — название, тарифы, лимиты, ноды и маршруты.
2. **Тарифы** — публикация, сроки, устройства, трафик и пробный период.
3. **Серверы** — доступность, вес и приём новых клиентов.
4. **Почта** — SMTP/IMAP и тестовое письмо.
5. **Резервные копии** — ручная контрольная копия.
6. **Безопасность** — новый пароль администратора и при необходимости 2FA.

Платёжную ссылку задавайте только локально через настройки. В публичном
репозитории она намеренно отсутствует.

## 9. Проверка перед запуском

Выполните полный тест:

1. зарегистрировать пользователя;
2. подтвердить e-mail;
3. связать Telegram;
4. создать заказ;
5. нажать «Оплатить»;
6. подтвердить платёж администратором;
7. получить ссылку и QR подписки;
8. подключить HAPP;
9. проверить продление, изменение тарифа и отказ платежа;
10. создать тикет;
11. создать резервную копию и восстановить её на тестовой машине.

Автоматические тесты проекта:

```bash
python3 -m unittest discover -s vpn-shop -p 'test_*.py'
python3 -m unittest discover -s vpn-bot -p 'test_*.py'
python3 -m unittest discover -s migration -p 'test_*.py'
python3 scripts/home-vpn-setup.py validate --config config/config.example.json
```

## 10. Обновление

Перед обновлением:

```bash
sudo home-vpn-restore create
git pull --ff-only
sudo bash install.sh
```

Выберите нужный компонент. Установщик не удаляет существующие базы. После
обновления проверьте службы и журнал.

## 11. Перенос существующих клиентов

Сначала выполните только отчёт:

```bash
cp migration/nodes.example.json nodes.json
python3 migration/migrate_existing_clients.py nodes.json --report before-migration.json
```

Не запускайте изменение клиентов, пока отчёт, inbound ID, домены подписок и
резервная копия не проверены. Подробности находятся в `migration/README.md`.
