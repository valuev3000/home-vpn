# Оплата HOME-VPN: ручной режим и ЮKassa

Версия: **0.0.3-pre**.

Одновременно работает только один способ оплаты:

- `manual` — текущая ручная оплата; подписка временно активируется, администратор подтверждает или отклоняет поступление денег;
- `yookassa` — автоматическая оплата; подписка создаётся только после подтверждённого платежа ЮKassa.

Параметры можно менять в **Админ-панель → Оплата**: активный режим, ручную ссылку, Shop ID, секретный ключ, адрес API и URL возврата. Подключённый Telegram-бот автоматически получает режим и готовые ссылки заказов через API сайта. Платёжный секрет боту не передаётся.

## Настройка по SSH

```bash
sudo home-vpn-setup payment
```

Выберите `manual` или `yookassa`. Для ЮKassa мастер запросит `Shop ID` и секретный ключ. При консольной настройке ключ записывается с правами `0600` в `/etc/vpn-shop.env`; при настройке на сайте — хранится в базе в зашифрованном виде. В обоих случаях он не попадает в `config.json`, HTML, API бота, журналы и Git.

После настройки автоматического режима мастер покажет адрес уведомлений:

```text
https://my.domain.ru/api/payments/yookassa/webhook
```

Добавьте этот HTTPS-адрес в кабинете ЮKassa для событий `payment.succeeded` и `payment.canceled`. Публичный сайт должен быть доступен по TLS 1.2 или новее на поддерживаемом ЮKassa порту.

## Переключение в панели

Откройте **Админ-панель → Настройки сервиса → Способ оплаты**. В браузере можно переключить уже настроенный режим, но секретный ключ там не отображается и не меняется. Если ключ не задан, включить ЮKassa через панель нельзя.

## Логика автоматической оплаты

1. HOME-VPN создаёт заказ и фиксирует сумму, тариф, срок, устройства и трафик.
2. При нажатии «Оплатить» сервер создаёт платёж с уникальным `Idempotence-Key` и переводит заказ в состояние ожидания ЮKassa. Десятиминутный таймер прекращается, отмена заказа блокируется.
3. Пользователь оплачивает на странице ЮKassa.
4. При возврате пользователя или входящем webhook HOME-VPN запрашивает платёж непосредственно через API ЮKassa.
5. Сверяются ID платежа, ID заказа в metadata, сумма и валюта RUB. Только статус `succeeded` вместе с `paid=true` запускает выдачу подписки.
6. Повторное уведомление безопасно: активный заказ второй раз не применяется.

Если деньги приняты, но узел временно не смог создать подписку, заказ получает статус «Оплачено, требуется обработка». Повторная проверка не требует новой оплаты.

## Проверка

```bash
sudo home-vpn-setup doctor
sudo systemctl status vpn-shop
journalctl -u vpn-shop -n 100 --no-pager
```

Сначала используйте тестовый магазин ЮKassa. Проверьте успешный платёж, отмену, повторный webhook, неверную сумму и временную недоступность основной ноды.
