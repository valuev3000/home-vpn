# HOME-VPN

Текущая предварительная версия: **0.0.5-pre**. Инструкция установки, миграции и отката:
[docs/installation-0.0.5-pre.md](docs/installation-0.0.5-pre.md).

Самостоятельно размещаемый кабинет для 3x-ui: сайт пользователей, тарифы, заказы, подписки, Telegram-бот, уведомления, тикеты, мониторинг узлов и административная панель.

Полная пошаговая инструкция для чистой однонодовой установки (DNS, TLS,
firewall, Telegram и проверка): [docs/installation.md](docs/installation.md).
Резервное копирование и восстановление: [docs/backup-and-restore.md](docs/backup-and-restore.md).
Схема 11 подключений 3x-ui: [docs/3x-ui-protocols.md](docs/3x-ui-protocols.md).
Выбор одной из трёх многосерверных архитектур: [docs/topology-installation.md](docs/topology-installation.md).

## Единая команда установки

Запустите интерактивный мастер непосредственно на российской управляющей VPS-1.
Для новой установки мастер использует распределённую схему: VPS-1 — сайт/API;
VPS-2 — первая зарубежная 3x-ui/Xray-нода, Telegram-бот и loopback-only
bot-admin; VPS-3 и далее — дополнительные 3x-ui-ноды. Число VPN-нод не
ограничено. Существующие inbounds, UUID, клиенты, сертификаты и ссылки не
переустанавливаются.

Одна команда для установки, обновления, полного backup, восстановления или удаления:

```bash
curl -fsSLo /tmp/home-vpn-install.sh https://raw.githubusercontent.com/valuev3000/home-vpn/main/install-single-node.sh && sudo bash /tmp/home-vpn-install.sh
```

Мастер считает текущую VPS управляющей (`local`), спрашивает `root@IP` VPS-2,
число дополнительных нод и адрес каждой из них. SSH-порт запрашивается только
после ответа `y` на вопрос, отличается ли он от 22. План сохраняется в
`/root/home-vpn-topology.json` без паролей и
токенов. Универсальный topology CLI с modes 1/2/3 сохранён для прежних установок
и ручной автоматизации.

Для удалённых VPS укажите SSH в формате `root@IP`. Если вход по ключу
ещё не работает, системный `ssh-copy-id` один раз запросит пароль каждой VPS и
установит созданный на управляющей VPS ключ. Пароль не читает Python-код, он не
попадает в plan, командную строку или Git.

Для управляющей VPS-1 заранее направьте DNS домена сайта на её
публичный IP и откройте TCP/80 и TCP/443. Если путь к сертификату оставить
пустым, мастер автоматически выпустит Let's Encrypt без email и настроит его
продление.

На выбранной зарубежной ноде (по умолчанию VPS-2) устанавливаются `vpn-bot`,
`bot-admin` и loopback Telegram egress рядом с её 11 VPN-подключениями; сайт
остаётся на VPS-1 и общается с ботом через HTTPS API. Панель бота остаётся на
loopback этой ноды и публикуется сайтом VPS-1 через постоянный SSH-туннель —
публичный порт `8090` не открывается. Сам Telegram Bot API использует HTTPS, а
не MTProto; аварийный MTProto остаётся отдельным inbound выбранной VPN-ноды.

Перед первым изменением мастер выполняет read-only аудит всех VPS, создаёт
на каждой роли архив `prechange`, проверяет `tar`, SQLite и SHA-256 и прекращает
работу при любой ошибке. После создания служебного XHTTP-клиента он сравнивает
отпечаток всех прежних inbounds и клиентов 3x-ui. Домен панели 3x-ui и текущий
REALITY SNI определяются автоматически, когда SSH по ключу уже доступен; иначе
мастер спрашивает их интерактивно.

Мастер также определит установленный HOME-VPN и покажет меню установки, обновления,
создания/восстановления полного backup, проверки безопасности и удаления. Для новой однонодовой VPS домены можно передать флагами
`--site-domain vpn.example.com --panel-domain panel.example.com`; если их нет,
мастер запросит домены только после неудачного автоопределения.

В modes 1/2 пункт обновления проходит по управляющей VPS и всем иностранным
нодам: обновляются только файлы HOME-VPN, backup units и edge-заглушки; базы,
секреты, 3x-ui, inbounds и клиенты не пересоздаются. Пункт backup создаёт полный
архив управляющей VPS и запускает проверенный KIT/3x-ui backup отдельно на
каждой иностранной ноде. Удаление снимает сайт, панели, bot egress, cascade и
edge-заглушки, восстанавливает прежний `ip_forward`, но сохраняет VPN-панели и
клиентов. Распределённое восстановление намеренно остаётся ручной операцией в
окно работ, поскольку атомарно откатить несколько VPS невозможно.

Ошибочный ответ не завершает мастер: он показывает причину и повторяет вопрос.
Это относится ко всем проверяемым полям и контрольным подтверждениям; в запросе
опасной контрольной фразы `0` отменяет операцию.

На VPS с существующей 3x-ui домен панели и REALITY SNI определяются из её базы,
когда это возможно. Обновление сохраняет базы,
пароли и пользователей; удаление HOME-VPN не удаляет 3x-ui и её клиентов.

DNS A-записи сайта и панели должны заранее указывать на VPS. Полный порядок и
режим `--plan-only`: [docs/installation.md](docs/installation.md).

Если мастер обнаружит существующую 3x-ui, он предложит два режима:

1. сохранить панель, inbounds, клиентов, подписки и firewall, добавив HOME-VPN;
2. после проверенного backup удалить VPN/HOME-VPN стек и выполнить чистую установку.

Второй режим не форматирует ОС или диск, но безвозвратно очищает рабочую базу
3x-ui после отдельной контрольной фразы. Для production используйте первый.

Для автоматизации topology installer можно по-прежнему запускать отдельно с
рабочей станции после создания локального плана без секретов:

```bash
git clone https://github.com/valuev3000/home-vpn.git
cd home-vpn
python3 scripts/install-home-vpn-topology.py --config topology.local.json
python3 scripts/install-home-vpn-topology.py \
  --config topology.local.json \
  --apply --confirm 'INSTALL HOME VPN TOPOLOGY'
python3 scripts/smoke-home-vpn-topology.py --config topology.local.json
```

## Установка с выбором компонента

```bash
git clone https://github.com/valuev3000/home-vpn.git
cd home-vpn
sudo bash install.sh
```

Мастер обнаруживает установленные компоненты и позволяет установить, обновить,
перенастроить или полностью удалить сайт, Telegram-бот с собственной защищённой
панелью, домен/TLS, VLESS XHTTP/REALITY, сайт-заглушку и SMTP/IMAP.
В документации используются только примеры:
`192.168.1.50` — ваш IP, `my.domain.ru` — ваш домен.

## Порядок установки

1. Установите **3x-ui**, запустите её и создайте API-токен. Inbound можно
   подготовить вручную либо создать отдельным компонентом мастера.
2. Скопируйте этот репозиторий на сервер с основной панелью 3x-ui.
3. Запустите мастер:

   ```bash
   sudo bash install.sh
   ```

4. Выберите действие и компоненты. Сайт, бот, домен/TLS, VLESS, заглушка и
   почта устанавливаются независимо.
5. При добавлении ноды сайт запросит API-токен и автоматически получит inbound
   ID, названия маршрутов, протоколы и транспорты. Если нода недоступна,
   сохранится ручная конфигурация.
6. Для последующих операций используйте мастер либо команды:

   ```bash
   home-vpn-manager status
   sudo bash install.sh
   sudo home-vpn-setup configure
   sudo home-vpn-setup tls
   sudo home-vpn-setup doctor
   ```

Обычный компонентный мастер не устанавливает и не удаляет саму 3x-ui. Мастер
топологии, напротив, устанавливает зафиксированный SHA-256 набор 3x-ui с 11
подключениями на чистых нодах; несовместимую существующую конфигурацию он не
удаляет. Ручной мастер VLESS создаёт только новый inbound после просмотра.

## Что настраивается

- цены для каждого количества устройств;
- максимальное количество устройств;
- лимит трафика в ГБ (`0` означает без ограничения);
- периоды, количество дней и ценовые множители;
- пробный тариф;
- валюта;
- имя, страна и флаг основной ноды;
- любое число дополнительных 3x-ui-нод;
- автоматическое получение inbound ID и таблицы маршрутов непосредственно из каждой 3x-ui-ноды;
- существующие домены подписок;
- внешний способ оплаты.

Общая конфигурация хранится в `/etc/home-vpn/config.json`. Токены и пароли находятся только в `/etc/vpn-shop.env` и `/etc/vpn-bot.env` с правами `600`.

Название сервиса, слоган, подзаголовок, тарифы, цены, число устройств, трафик, ноды и маршруты также редактируются в **Админ-панель → Настройки сервиса**. Изменения применяются сразу и автоматически появляются в Telegram-боте. Для ноды доступна кнопка синхронизации с 3x-ui. API-токены в веб-форме не показываются: там задаётся только имя переменной окружения, например `FOREIGN_XUI_TOKEN`.

В **Админ-панель → Тарифы** доступен расширенный каталог: публикация и архивирование, дата начала новой цены, персональные предложения, пробный период, тарифы продления и промокоды. При создании заказа название, сумма, срок, устройства и трафик копируются в заказ. Поэтому последующее изменение каталога не меняет уже выставленные заказы.

В карточке пользователя собраны его Telegram, все подписки, устройства, заказы и платежи, уведомления, тикеты и журнал административных действий. Там же можно заблокировать аккаунт, изменить лимиты, добавить дни, отвязать устройства, сбросить ссылку подписки и объединить дублирующиеся аккаунты.

Раздел **Админ-панель → Серверы** показывает доступность, CPU, RAM, диск, сеть, трафик и активных пользователей. Вес, запрет выдачи новым пользователям и режим обслуживания задаются отдельно для каждого сервера. Новому заказу автоматически назначается наименее загруженный доступный сервер с учётом веса; назначение сохраняется в заказе для последующего развёртывания маршрута.

Домен, сертификат и закрытый TLS-ключ меняются только из консоли:

```bash
sudo home-vpn-setup tls
```

Мастер пытается найти сертификат, уже используемый 3x-ui. Само приложение
всегда слушает `127.0.0.1:8080`: на свободном публичном порту устанавливается
TLS reverse proxy Nginx, а в mode 3 занятый Xray порт 443 получает проверяемый
fallback на HOME-VPN. Панель бота также остаётся на loopback и публикуется
через тот же TLS-вход сайта.

## Оплата

В репозитории **нет банковской ссылки, реквизитов и ключей ЮKassa**. Одновременно включается только один режим: ручная оплата с подтверждением администратором или автоматическая оплата через ЮKassa. Режим, ручная ссылка, Shop ID, секретный ключ, API URL и URL возврата настраиваются в **Админ-панель → Оплата**. Секрет хранится зашифрованно и не передаётся подключённому Telegram-боту; бот получает готовые ссылки заказов через API сайта. Первичную настройку также можно выполнить командой `sudo home-vpn-setup payment`. Подробности: [docs/payment-yookassa.md](docs/payment-yookassa.md).

Автоматическое обновление из GitHub временно отключено. Менеджер обновляет компоненты только из локального каталога проекта и сам не выполняет `git pull`.

## Несколько серверов

Сайт может управлять одной или несколькими удалёнными 3x-ui-нодами. Новые
клиенты создаются на назначенной ноде, и последующие операции выполняются там же.
Поддерживаются прямой режим, каскад через RU и одиночная зарубежная установка.
Интерактивный сценарий и ограничения описаны в
[инструкции по топологиям](docs/topology-installation.md).

Если серверы уже настроены и содержат клиентов, сначала выполните безопасную инвентаризацию:

```bash
cp migration/nodes.example.json nodes.json
python3 migration/migrate_existing_clients.py nodes.json --report before-migration.json
```

Скрипт миграции не записывает токены в отчёт и по умолчанию ничего не изменяет. Подробности находятся в [migration/README.md](migration/README.md).

## Telegram-бот и панели

Сайт, админ-панель и панель Telegram-бота работают на управляющей VPS: обычно
центральной RU VPS, а в mode 3 — на единственной иностранной VPS.
Обращения бота к Telegram API проходят через локальный балансировщик и
маскированные VLESS/XHTTP-маршруты зарубежных VPS. Обращения к локальному API сайта через
этот маршрут не отправляются.

## Обновление

На узлах 3x-ui используется совместимое локальное резервное копирование:

- ежедневный архив создаётся штатной командой `kit backup`;
- перед упаковкой выполняется `PRAGMA integrity_check` базы 3x-ui;
- архив и SHA-256 сохраняются в `/root` с правами root;
- архив распаковывается во временный каталог для проверки;
- срок хранения задаётся через `KIT_BACKUP_RETENTION_DAYS` (по умолчанию 30 дней).

Перед ручным обновлением можно запустить копирование немедленно:

```bash
sudo systemctl start home-vpn-kit-backup.service
sudo systemctl status home-vpn-kit-backup.service
```

Старая backup-панель, pull-agent и второй backup-сервер удалены. Архив KIT
локален для узла и не защищает от потери VPS. Экспорт в
off-site-хранилище следует выполнять средствами провайдера или NAS без права удаления
со стороны VPN-узла. Подробности: [docs/backup-and-restore.md](docs/backup-and-restore.md).

После замены файлов выполните `sudo systemctl restart vpn-shop vpn-bot` на соответствующих серверах.

## Безопасность

Не публикуйте `.env`, базу данных, TLS-ключи, реальные скрытые URL, Telegram-токен или API-токены 3x-ui. Перед публичным запуском замените все пароли и используйте TLS. 2FA администратора доступна как дополнительная, но не обязательная настройка.
