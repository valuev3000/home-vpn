# HOME-VPN

Текущая предварительная версия: **0.0.3-pre**. Инструкция установки и обновления:
[docs/installation-0.0.3-pre.md](docs/installation-0.0.3-pre.md).

Самостоятельно размещаемый кабинет для 3x-ui: сайт пользователей, тарифы, заказы, подписки, Telegram-бот, уведомления, тикеты, мониторинг узлов и административная панель.

Полная пошаговая инструкция: [docs/installation.md](docs/installation.md).
Резервное копирование и восстановление: [docs/backup-and-restore.md](docs/backup-and-restore.md).
Мультисерверная backup-панель и перенос на новый IP: [docs/multi-server-backup.md](docs/multi-server-backup.md).

## Установка с выбором компонента

```bash
git clone https://github.com/YOUR_ACCOUNT/home-vpn.git
cd home-vpn
sudo bash install.sh
```

Мастер обнаруживает установленные компоненты и позволяет установить, обновить,
перенастроить или полностью удалить сайт, Telegram-бот с собственной защищённой
панелью, домен/TLS, VLESS XHTTP/REALITY, сайт-заглушку, SMTP/IMAP, backup-сервер
и отдельный backup-агент каждого рабочего узла.
В документации используются только примеры:
`192.168.1.50` — ваш IP, `my.domain.ru` — ваш домен.

## Порядок установки

1. Установите **3x-ui**, запустите её и создайте API-токен. Inbound можно
   подготовить вручную либо создать отдельным компонентом мастера.
2. Скопируйте этот репозиторий на сервер с основной панелью 3x-ui.
3. Запустите мастер:

   ```bash
   sudo bash install.sh
   ```

4. Выберите действие и компоненты. Сайт, бот, домен/TLS, VLESS, заглушка,
   почта и backup-сервер устанавливаются независимо.
5. При добавлении ноды сайт запросит API-токен и автоматически получит inbound
   ID, названия маршрутов, протоколы и транспорты. Если нода недоступна,
   сохранится ручная конфигурация.
6. Для последующих операций используйте мастер либо команды:

   ```bash
   home-vpn-manager status
   sudo bash install.sh
   sudo home-vpn-setup configure
   sudo home-vpn-setup tls
   sudo home-vpn-setup backup-remote
   sudo home-vpn-setup doctor
   ```

Проект не устанавливает и не удаляет саму 3x-ui. Мастер VLESS создаёт только
новый inbound после предварительного просмотра и явного подтверждения;
существующие inbound не меняются.

## Что настраивается

- цены для каждого количества устройств;
- максимальное количество устройств;
- лимит трафика в ГБ (`0` означает без ограничения);
- периоды, количество дней и ценовые множители;
- пробный тариф;
- валюта;
- имя, страна и флаг основной ноды;
- любое число дополнительных 3x-ui-нод;
- автоматическое получение inbound ID и таблицы маршрутов непосредственно из каждой 3x-ui-ноды;
- существующие домены подписок;
- внешний способ оплаты.

Общая конфигурация хранится в `/etc/home-vpn/config.json`. Токены и пароли находятся только в `/etc/vpn-shop.env` и `/etc/vpn-bot.env` с правами `600`.

Название сервиса, слоган, подзаголовок, тарифы, цены, число устройств, трафик, ноды и маршруты также редактируются в **Админ-панель → Настройки сервиса**. Изменения применяются сразу и автоматически появляются в Telegram-боте. Для ноды доступна кнопка синхронизации с 3x-ui. API-токены в веб-форме не показываются: там задаётся только имя переменной окружения, например `PL_XUI_TOKEN`.

В **Админ-панель → Тарифы** доступен расширенный каталог: публикация и архивирование, дата начала новой цены, персональные предложения, пробный период, тарифы продления и промокоды. При создании заказа название, сумма, срок, устройства и трафик копируются в заказ. Поэтому последующее изменение каталога не меняет уже выставленные заказы.

В карточке пользователя собраны его Telegram, все подписки, устройства, заказы и платежи, уведомления, тикеты и журнал административных действий. Там же можно заблокировать аккаунт, изменить лимиты, добавить дни, отвязать устройства, сбросить ссылку подписки и объединить дублирующиеся аккаунты.

Раздел **Админ-панель → Серверы** показывает доступность, CPU, RAM, диск, сеть, трафик и активных пользователей. Вес, запрет выдачи новым пользователям и режим обслуживания задаются отдельно для каждого сервера. Новому заказу автоматически назначается наименее загруженный доступный сервер с учётом веса; назначение сохраняется в заказе для последующего развёртывания маршрута.

Домен, сертификат и закрытый TLS-ключ меняются только из консоли:

```bash
sudo home-vpn-setup tls
```

Мастер пытается найти сертификат, уже используемый 3x-ui, проверяет его и включает встроенный HTTPS сайта. Nginx проектом не устанавливается и не требуется. При установке мастер проверяет публичный порт: если он свободен, сайт запускается напрямую; если порт уже занят существующим прокси, сайт остаётся на `127.0.0.1:8080`, а мастер сообщает адрес для проксирования.

## Оплата

В репозитории **нет банковской ссылки, реквизитов и ключей ЮKassa**. Одновременно включается только один режим: ручная оплата с подтверждением администратором или автоматическая оплата через ЮKassa. Режим, ручная ссылка, Shop ID, секретный ключ, API URL и URL возврата настраиваются в **Админ-панель → Оплата**. Секрет хранится зашифрованно и не передаётся подключённому Telegram-боту; бот получает готовые ссылки заказов через API сайта. Первичную настройку также можно выполнить командой `sudo home-vpn-setup payment`. Подробности: [docs/payment-yookassa.md](docs/payment-yookassa.md).

Автоматическое обновление из GitHub временно отключено. Менеджер обновляет компоненты только из локального каталога проекта и сам не выполняет `git pull`.

## Несколько серверов

Основная нода — центральная 3x-ui, с которой сайт создаёт клиентов и получает общую подписку. Дополнительные ноды описываются в `nodes` без ограничения количества. Маршрут содержит имя, `inbound_id`, протокол и транспорт.

Если серверы уже настроены и содержат клиентов, сначала выполните безопасную инвентаризацию:

```bash
cp migration/nodes.example.json nodes.json
python3 migration/migrate_existing_clients.py nodes.json --report before-migration.json
```

Скрипт миграции не записывает токены в отчёт и по умолчанию ничего не изменяет. Подробности находятся в [migration/README.md](migration/README.md).

## Telegram-бот на отдельном сервере

Скопируйте каталог `vpn-bot` на сервер бота, заполните `/etc/vpn-bot.env` по примеру `config/vpn-bot.env.example` и включите сервис. Бот получает тарифы, устройства, трафик и список узлов с центрального API, поэтому отдельное редактирование цен на сервере бота не требуется.

## Обновление

Установщик включает лёгкие системные таймеры:

- ежедневная согласованная резервная копия баз сайта и 3x-ui, конфигурации и TLS-файлов;
- проверка целостности SQLite перед сохранением архива;
- хранение архивов 14 дней в `/var/backups/home-vpn` с правами только для root;
- проверка сайта каждые 5 минут с перезапуском только при недоступности `/health`.
- проверка каждые 6 часов: свободное место, свежесть резервной копии, срок TLS и состояние основных служб; результат доступен администратору без отдельной системы мониторинга.

Перед ручным обновлением можно запустить копирование немедленно:

```bash
sudo systemctl start home-vpn-backup.service
sudo systemctl status home-vpn-backup.service
```

Локальная копия защищает от ошибки приложения, но не от потери всего сервера. Для реальной установки каталог `/var/backups/home-vpn` необходимо дополнительно копировать на отдельный сервер или в закрытое объектное хранилище.

### Необязательный отдельный backup-сервер

В `0.0.2` хранилище и агенты устанавливаются как разные компоненты. На
выделенном backup-сервере запустите мастер и выберите **Backup-сервер и GUI**:

```bash
sudo bash install.sh
```

На каждом RU/PL/бот/дополнительном сервере тем же мастером выберите
**Backup-агент рабочего сервера**. Агент покажет публичный ключ. Вставьте его в
backup-панели через кнопку **Добавить сервер**, затем запустите первую копию:

```bash
sudo systemctl start home-vpn-full-backup.service
sudo systemctl status home-vpn-full-backup.service --no-pager
```

Backup-аккаунт не получает обычную командную оболочку: SSH принудительно
запускает только проверяющий приёмник. GUI позволяет добавлять, временно
отключать, повторно включать и безопасно удалять серверы. Полный порядок:
[docs/installation-0.0.2.md](docs/installation-0.0.2.md#8-установка-backup-сервера).

После замены файлов выполните `sudo systemctl restart vpn-shop vpn-bot` на соответствующих серверах.

## Безопасность

Не публикуйте `.env`, базу данных, TLS-ключи, реальные скрытые URL, Telegram-токен или API-токены 3x-ui. Перед публичным запуском замените все пароли и используйте TLS. 2FA администратора доступна как дополнительная, но не обязательная настройка.
