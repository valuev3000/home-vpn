# Security policy

Сообщайте об уязвимостях владельцу развёртывания приватно. Не создавайте публичный issue с токенами, ссылками подписок, дампами базы или деталями работающего сервера.

Перед публикацией репозитория проверьте, что в истории Git отсутствуют `.env`, базы, сертификаты, Telegram-токены, API-токены 3x-ui и реальные скрытые пути входа.

Поддерживаемая конфигурация предполагает TLS, firewall, rate limiting, Fail2ban, отдельного непривилегированного пользователя сервиса и права `600` на файлы окружения.
